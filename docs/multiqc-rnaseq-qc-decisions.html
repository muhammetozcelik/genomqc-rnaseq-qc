PRACTICAL RNA-SEQ QC GUIDE

From MultiQC output to a defensible decision

A transparent, sample-level workflow for research teams

MultiQC is excellent at aggregating quality-control results. The next challenge is deciding which samples need review, recording why, and making the decision reproducible.

1. Start with a structured export

Use a MultiQC JSON, TSV or CSV export that contains recognizable sample identifiers and the metrics relevant to your protocol. Keep the original MultiQC report alongside the structured export so every decision can be traced back to its source.

2. Make missing data visible

A missing metric is not a passing result. Record which values were available, which aliases were mapped, and which samples require manual review because a required field was absent.

3. Use thresholds that match the experiment

Read depth, Q30, retention, duplication, adapter content and GC deviation can all inform QC, but no single boundary is universal. Choose WARN and FAIL thresholds with reference to the assay, organism, library preparation, sequencing platform, study design and laboratory SOP.

4. Keep the reason beside the status

PASS, WARN and FAIL labels are only useful when a reviewer can see the metric, boundary and recommended next action that produced them. Store the rule profile with the report rather than leaving the decision logic in an analyst's memory.

5. Review the cohort, then archive the decision

Inspect individual flags in the context of the full cohort. Save a human-readable report and a machine-readable export so the project can be reviewed, compared or audited later.
