RNA-seq QC checklist: what to review before downstream analysis

A sample-level review structure for research teams

Quality control is not a single score. A useful review combines experimental context, per-sample metrics and a recorded next action.

1. Confirm the input and study context

Keep the original MultiQC report, the structured export and the run metadata together. Verify sample identifiers, assay type, organism, library preparation, read layout and the laboratory SOP before interpreting a threshold.

2. Review essential per-sample signals

For each sample, inspect the metrics relevant to the workflow: read count, base quality or Q30, adapter content, retained reads after trimming, mapping or assignment rate where available, duplication and GC distribution. A metric that is missing should trigger review; it is not evidence of a pass.

3. Compare samples with their cohort

Outliers are often more informative than a universal cutoff. Compare distributions across the same run and ask whether an unusual value follows the study design, expected biology, a batch effect or a technical issue.

4. Attach an action to every status

Use a simple decision queue: PASS for samples ready to proceed, WARN for samples that need documented review, and FAIL for samples that should stop until the issue is resolved. Keep the metric, boundary, reason and next action together.

5. Record the decision

Export a concise human-readable report plus structured data. The record should state the tool versions, rule profile, available metrics, reviewer and any exception made for the project. This prevents QC decisions from living only in an analyst's memory.

Common mistakes

Do not treat all RNA-seq duplication as a failure, apply thresholds without considering library preparation, or collapse missing values into zeros. Do not let an automated label replace qualified scientific review.
